# Speed-first interaction and competitor engineering review

2026-11-27 KST. VANTA 0.4.0 development only. Review of public primary documentation, not a head-to-head timing benchmark or a source-code port. Keep strict source preservation, audio payload/timeline checks, strict decode, non-overwriting publication and current defaults. Neither a new codec nor a new version is authorized by this review.

## Three priority axes

1. Encoder objective: explicit fast vs balanced vs compression efficiency, independent of OS scheduling. Keep target, preset and codec visible; faster does not imply quality equivalence.
2. Queue submission order: user-selected ready job first/up/down before start; preserve per-job settings, output filenames, no implicit cancellation or preemption. Visible order must equal submitted array order; sort-by-column disabled until a clearly labeled display-only sorting design exists. With concurrent workers exact start/finish order can differ. Add nonpreemptive hold and per-item cancellation only after explicit state machine and cleanup tests.
3. OS resource policy: proposed BelowNormal / Normal / AboveNormal for actual child encoder only, default unchanged. No High/RealTime. OS CPU scheduling priority is not thread count, CPU cap, encoding preset, or algorithmic improvement. [Microsoft priorities](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.processpriorityclass), [scheduling](https://learn.microsoft.com/en-us/windows/win32/procthread/scheduling-priorities), [QoS](https://learn.microsoft.com/en-us/windows/win32/procthread/quality-of-service). Investigate separately Windows actual child vs Chocolatey shim, setting/readback, immediate exit/cancel/permission failure, whether validation uses separate policy, UI responsiveness. Test unloaded and controlled competing foreground CPU, measure total elapsed and foreground latency p95, same output SHA, full validation, process tree cleanup. Priority is user preference not general acceleration; no change implemented.

## Proposed views (not screenshot or implemented full redesign)

Single: source metadata/duration; three compact objectives; current applied codec/preset/height/bitrate; source vs budget size and prior/reference ETA; optional preview; collapsed advanced settings (thread budget, CPU priority, diagnostics, explicitly experimental split); fixed footer with actual plan and save, stage, progress, remaining time, elapsed. Preserve current validated separate-file rule. Do not hide quality uncertainty.

Batch: common profile, speed, parallel jobs and resource policy; visible submission-order controls; each row input/output, plan/size, state, encoding progress or named validation phase, per-job ETA; preflight queue range/coverage, total settled vs verified; selected job inspector (individual overrides, source/output, details, retry/play); explicit cancel one/stop after current vs cancel all in future. Do not present verified count as byte or time progress. With unknown ETA show reason, not zero.

## Algorithm roadmap and gates

- P0: throughput under quality and size constraints, no source/timeline/audio/decode regression. Retain existing symmetric comparison results. Separate future directional objective preregistered before new data: candidate bytes <=1.05 * anchor bytes, mean SSIM >= anchor -0.001, worst second >= anchor -0.005, same dimensions/frame clock/copied audio/full decode, at least 15% median end-to-end gain on paired repetitions. Better quality or smaller files should not automatically fail a product upper-bound objective; do not retroactively promote previously excluded symmetric pairs. Add visual review on natural material and report bitrate/quality trade-offs.
- GPU: measure actual device capabilities and initialize actual short encode; exact device/driver/binary, CPU baseline, CPU decode+GPU encode and device-resident pipeline separately, include upload/download, filtering, strict CPU output validation and publication; reject unsupported format/driver and do not silently fallback. Test source/output duration, VFR, NTSC, audio, cancellation and collision before exposure.
- x265: inspect pool/frame threads/WPP under 1/2 workers; resource measurements and full elapsed; prior decoder/thread tuning negative cases retained.
- Budgeted adaptive selection: use cheap metadata first, sample only by explicit request and expected benefit greater than sample+quality+validation cost; retain candidate/fallback evidence, evaluate held-out content, no first-run guaranteed estimates. Existing 9-mode search cost 3.78–6.08x anchor excluding external quality; short sampling 11.12s vs full AVC encode8.05s. Reject expensive global search.
- Queue policy: keep user priority first. Compare FIFO, shortest-first for mean completion, longest-first for makespan, and bounded age/fairness under arrivals with predicted vs actual durations; previous five queue replays only, no automatic reorder. Report makespan, time to selected-job completion, mean/p95 wait, throughput, exact validation and peak resources separately.
- UX quick wins: plan visibility, manual queue order now; next selected job inspector and live throughput; then stop/hold/retry state machine; explicit opt-in preview. Do not let UI add costly background scans.
- Defer decorative animations, codec zoo, distributed processing and automatic watch folders. No version advance.
